# PulseBoard

A personal, private, single-file PWA dashboard: curated morning and night briefings, arXiv research digests, weather, routines, and secular teachings. No accounts, no servers of its own, no analytics, no tracking.

**Live:** https://pulseboard-arnabcodes.vercel.app

## Architecture

| File | Role |
|---|---|
| `index.html` | The entire app (UI + logic) in one file |
| `sw.js` | Service worker (v14): precache, network-first navigation/data, stale-while-revalidate images, inline offline page, self-update |
| `manifest.json` | PWA manifest — installable, edition shortcuts, screenshots |
| `pulse_feed.json` | Daily feed (stories + papers), generated by the pipeline below |
| `teachings_db.json` | Hand-curated teachings pool (16 entries; some with YouTube links) |
| `articles_db.json` | Hand-curated evergreen stories + the Mind & Habits column |
| `scripts/curate.py` | The daily curation pipeline |
| `.github/workflows/` | Curation cron, feed validation, tests, weekly link health |
| `vercel.json`, `404.html` | Deploy config (security/cache headers) and themed 404 page |
| `tests/` | pytest suite for the curator + feed/link checkers |

Deploy path: local → GitHub (`ArnabCodes/pulseboard`, `main`) → Vercel (static). The app fetches the data JSONs at runtime — nothing is baked into `index.html`.

## Local development

```bash
cd PulseApp
python3 -m http.server 8793     # any free port 8788+
# open http://localhost:8793
```

Don't open via `file://` — the service worker and `fetch()` need http(s).

**E2E conventions:**
- PIN `1234` is the test PIN (the vault setup screen will ask you to create one on first run).
- Use ports 8788+ so parallel test sessions don't collide.
- `?edition=morning` / `?edition=night` forces an edition (the app otherwise picks by local time: morning 5:00–18:00, night 18:00–5:00).

## Data pipeline

A GitHub Action ("Autonomous Daily Pulse Curation") runs `scripts/curate.py` at **04:00 and 19:00 UTC** (06:00 and 21:00 Israel time), commits a fresh `pulse_feed.json`, and Vercel deploys it. The app pulls the feed after every unlock (network-first, cached copy for offline).

Three channels, merged:

1. **Hand-curated** (`articles_db.json`): evergreen stories and the Mind & Habits column, always included verbatim.
2. **arXiv papers**: recent submissions to `quant-ph` / `cond-mat.mes-hall` / `physics.app-ph`, keyword-scored against the research profile (NMR & spin control, NV/diamond sensing, Floquet, coherence).
3. **Multi-source news**: RSS from a curated, spectrum-tagged outlet pool. Balance is structural — topic quotas, max one story per outlet per topic, and a corroboration boost for stories covered by several outlets (especially across the political spectrum; the app shows a lean chip per story).

**Honesty policy — extractive only.** Paper TLDRs and takeaways are the authors' own abstract sentences; news briefings are the outlet's own words. Nothing is paraphrased, rewritten, or invented.

**Images.** A story's cover is its own og:image / feed image; missing or duplicated covers get a deterministic, distinct fallback from per-category Unsplash pools (`FALLBACK_CATEGORY_IMAGES` in `scripts/curate.py`, each URL verified 200 before it was added). `ensure_distinct_covers()` guarantees no two stories in a feed share a cover — a hard app requirement.

## Privacy model

- **No servers, no accounts, no analytics.** The only network calls are content fetches (the deployed feed, open-meteo weather) and image CDNs.
- **The PIN vault**: AES-GCM (WebCrypto) — the PIN derives the key, content is encrypted in `localStorage`. Biometric/WebAuthn and trusted-device unlock are *convenience layers* over the same vault, not a weakening of it (the device key is also local).
- **No geolocation.** Weather uses fixed coordinates.
- All rendering, decryption, and state live in the browser; clearing site data wipes everything.

## How to add content

**A teaching** — append to `teachings_db.json` (`{"teachings": [...]}`):
```json
{
  "id": "kebab-case-id",
  "edition": "morning" | "night",
  "tradition": "Zen • source line",
  "theme": "Equanimity",
  "quote": "…",
  "reflection": "one short paragraph",
  "story": "where it comes from, honestly",
  "source": "attribution",
  "videoUrl": "https://www.youtube.com/watch?v=…",   // optional
  "videoLabel": "Alan Watts — …"                      // optional
}
```

**A hand-curated story** — append to `articles_db.json`:
```json
{
  "id": "hand-…",
  "edition": "morning",
  "category": "Geopolitics & Global" | "Tech & AI" | "Quantum & Physics" | "Mind & Habits",
  "title": "…", "dek": "one-line standfirst",
  "content": "paragraphs separated by \n\n (the app renders the breaks)",
  "whyItMatters": "one honest sentence",
  "source": "Outlet", "sourceUrl": "https://…",
  "image": "https://…/cover.jpg"   // optional — a distinct pool fallback is assigned if empty
}
```

**Fallback image pools** — `FALLBACK_CATEGORY_IMAGES` in `scripts/curate.py`. Keep any URL you add curl-verified (HTTP 200 with a browser UA); a guessed Unsplash photo id 404s silently.

## Quality & accessibility wave (this release)

- **Focus trap** — while any full-screen page is open, Tab/Shift-Tab cycle within the page layer; focus moves into the page on open and returns to the trigger on close.
- **Keyboard shortcuts** — `/` opens (or focuses) search; Escape closes the top page. Both skip keystrokes while you're typing in a field.
- **Settings → About** — app version, storage used (`navigator.storage.estimate()`), a "Check for updates" button (service-worker update check; shows a reload button when one is ready) and "Clear cached files".
- **Settings → Your data** — a plain-words honesty card listing exactly what is stored where (see the privacy model below).
- **Haptics toggle** — switching it on now gives a short test buzz, so you feel what you're toggling.
- **Day-close** — drafts autosave to `sessionStorage` (restored on reopen, cleared on close); an honest one-line summary of completed tasks above the finish button; an optional 5-emoji mood check-in stored with the day.
- **Weekly digest** — a reading & practice section (briefings opened, minutes-read estimate, meditation sessions/minutes) and a 7-dot mood trend with honest gaps for missed days; on Friday evenings a dismissible chip nudges you to the weekly review (once per ISO week).
- **Teachings** — selectable session lengths (2/5/10/15 min, remembered); breath-pacing patterns (Box 4-4-4-4, Calm 4-7-8, Coherent 5-5) driving the orb; favorite teachings with a ★-filter chip; a copy-quote button. Under `prefers-reduced-motion` the orb keeps moving but at half speed (the pacing is the point of the feature) — page transitions are skipped entirely.
- **Saved view** — saved stories group under Today / This week / Earlier, newest first. The papers read-later queue shows an "Up next" hint and orders itself up-next-first.

## Testing

```bash
python3 -m pytest tests/ -q          # full suite: curator, feed, static app checks, data files
node --check <extracted-script.js>  # the inline script, verified automatically by tests/test_static.py
python3 tests/validate_feed.py      # feed shape invariants (add --check-images for reachability)
```

`tests/test_static.py` extracts the single inline `<script>` from `index.html`, runs `node --check` on it (skipped if node is absent), fails on any NEW duplicate function declaration, and verifies every literal `getElementById('X')` has a matching `id="X"` somewhere in the file. `tests/test_data_files.py` pins the shapes of `teachings_db.json` / `deadlines.json` / `this_day.json`.

## What is stored where (settings → Your data, in detail)

- **Encrypted vault** (AES-GCM, PIN-derived key, in `localStorage`): tasks, routines, saved stories & papers, the day-close log including mood. The PIN never leaves the device and is never stored.
- **Plain `localStorage`** (non-sensitive by design): UI preferences (`pb_prefs`, incl. favorite teachings and breath pattern), read/unread story ids (capped at 500), reading-streak days, meditation and focus logs, the feed timestamp.
- **`sessionStorage`**: only the day-close draft — wiped the moment you close the day.
- **What leaves the device**: nothing of yours. The app fetches only public content — the deployed news/arXiv feed, open-meteo weather (fixed coordinates, no geolocation), and images from CDNs. No accounts, no analytics, no tracking; clearing site data wipes everything.

## CI

| Workflow | Trigger | What it does |
|---|---|---|
| `update-pulse.yml` | cron 04:00/19:00 UTC | runs the curator, commits the feed |
| `validate-feed.yml` | every push + after every curation run | feed parses; ≥1 story / ≥1 paper; required fields; unique ids; **distinct covers**; image reachability (warn-only) |
| `tests.yml` | every push | pytest over the curator's pure functions |
| `link-check.yml` | weekly (Mon 07:00 UTC) | teachings YouTube links (via thumbnail), every NEWS_SOURCES RSS URL, feed images; opens a GitHub issue listing broken links |

`tests/validate_feed.py` and `tests/link_check.py` are plain scripts — you can run both locally: `python3 tests/validate_feed.py --check-images` and `python3 tests/link_check.py`.

## Deploy notes

- `vercel.json` sets `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: geolocation=(), camera=(), microphone=()`; `index.html` and `sw.js` are always revalidated, images are immutable-cached, data JSONs get `max-age=300`.
- **No CSP is shipped on purpose**: the Tailwind Play CDN injects runtime `<style>` elements and inline config, which a strict CSP would break. If Tailwind is ever replaced with a build step, add a CSP then.
- A root `404.html` is served by Vercel (status 404) for any route that matches no static file.
- Service worker versioning: `sw.js` is on `pulseboard-v14`. To ship a new one, bump `CACHE_NAME` — the worker deletes old caches on activate and (on update, not first install) reloads open tabs once, with no app-side code.
